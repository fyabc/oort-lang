# OP 0006: 模块与导入系统

- **状态**：Draft
- **作者**：Oort 设计讨论
- **相关**：[OP 0001](0001-feature-layers-and-dialects.md)、[设计笔记 06](../design/06-language-syntax-design.md)

## 摘要

为 Oort 定义模块系统：模块身份、导入语法、查找路径、初始化顺序、循环依赖与可见性。
目标是用 AST 级模块替代 C++ 的 `#include` 文本包含。

## 动机

- 当前 `import` 语法可解析，但语义分析会报“未实现”。
- 头文件模型带来宏泄漏、ODR、重复解析、编译时间等问题；Oort 从一开始就应避免。
- DSL/方言（[OP 0001](0001-feature-layers-and-dialects.md)）需要模块级边界。

## 设计

### 1. 模块身份

- 一个 `.ort` 文件是一个模块。
- 模块名由文件路径 + 包根决定，而不是由内容声明决定；避免 C++ 头文件 guard 式重复。
- 每个模块编译一次并缓存；导入得到同一个模块对象。

### 2. 语法

```oort
import "math"                    # 导入模块，绑定到 math
import "math" as m               # 起别名
from "math" import sqrt, pow as power
```

（现有语法已支持上述形式。）

### 3. 查找路径

- 相对路径（以 `./`、`../` 开头）相对于当前模块目录；
- 绝对模块名相对于项目根/标准库路径；
- 可通过编译器选项增加搜索路径。

### 4. 初始化语义

- 默认**急切**：导入即执行模块顶层语句，且在实际使用前完成（与设计笔记 06 一致）。
- 模块顶层只允许定义与初始化；复杂副作用建议放到显式 `init()`。
- 重复导入只执行一次。

### 5. 循环依赖

- 允许模块图存在环，但初始化顺序需拓扑；环中模块看到未初始化绑定时报错。
- 首版可以禁止循环导入，给出清晰错误，后续再支持。

### 6. 可见性

- 默认公开所有顶层名字（玩具语言阶段）；
- 后续增加 `private`/`pub` 或下划线约定。
- 模块的方言（`#lang`）随模块记录，跨方言调用必须经过 FFI 边界。

### 7. 与类型系统的交互

- 静态模块导入时，类型信息立即可用（不依赖运行期）；
- 模块接口可单独检查，避免全程序重编译。

## 正交性检查

- 与宏：宏的可见性需与模块绑定，不能像 C 宏一样跨模块泄漏。
- 与方言：模块是方言边界。
- 与缓存/字节码：模块是编译单元与缓存键。

## 替代方案

1. **C++ 式文本包含**：放弃，问题太多。
2. **隐式自动导入标准库**：方便但不利于可读性；可作为预导入列表（prelude）。
3. **仅支持 `from ... import`**：表达力不足。

## 实现计划

1. 模块加载器：路径解析、缓存、模块对象。
2. 导入执行与绑定（急切）。
3. 循环检测与诊断。
4. 标准库模块与 prelude。
5. 与静态类型检查器对接。

## 未解决问题

- 模块名与包名的映射规则。
- 是否支持模块级可变全局状态（以及其初始化顺序）。
- 编译缓存与源码位置信息的持久化格式。
